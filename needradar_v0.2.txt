# NeedRadar 需求雷达 · 修订版 PRD

**版本**：V0.2（基于 V0.1 评审意见与数据源可行性调研修订）
**状态**：草案
**目标市场**：美国
**时间窗口**：主窗口 4 周滚动 + 1 周增量
**行业范围**：不限
**排序依据**：付费意愿 × 用户可进入性
**输出**：每周 Top 10 需求报告 + 证据链 + 验证实验建议

---

## 0. V0.1 → V0.2 变更摘要

1. **数据源按"是否有官方 API / 授权渠道"重新分层**，不再按信号强度分层。砍掉或降级所有无合法批量渠道的源（LinkedIn、Indeed、Glassdoor、Upwork、Fiverr、Kickstarter、Indiegogo、BBB、Quora、TikTok）。
2. **主窗口从 1 周改为 4 周滚动 + 1 周增量**，解决 P4/P5 信号在 1 周窗口内过于稀疏的问题。
3. **WPS 公式各分量全部给出可实现的定义**；置信度函数明确定义。
4. **新增"可进入性（Accessibility）"维度**，避免政府大额招标霸榜但对核心用户不可执行的问题。
5. **删除 P6 等级在排序公式中的权重**（P6 不进系统排序，改列为"验证结果"标签）。
6. **P 级判定改为规则优先、LLM 辅助**（招标金额、薪资、预算等用规则抽取）。
7. **重写成功指标**，聚焦精排准确率、重复主题率、用户留存；删除产品不可控指标。
8. **报告模板砍掉"竞争格局/决策人"两节**（幻觉高发区），改为明确标注"推测"的附录。
9. **里程碑按合规数据源重排**，第 1 周只接入有官方 API 的源。
10. **补充成本预算上限与回填产品机制**。

## 1. 背景与问题

创业者、产品经理、投资人和咨询顾问需要发现"有人愿意付费解决"的需求，但现有方式存在明显问题：

- 人工搜索、访谈、看竞品，速度慢、主观性强、无法规模化；
- 短窗口内公开数据中付费信号稀疏，噪音大；
- "紧缺"不等于"付费"，大量抱怨背后没有预算；
- 招聘、招标、外包等强付费信号分散在不同平台，且多数平台无合法批量采集渠道；
- 缺少从"信号发现"到"付费验证"的结构化流程。

因此，本产品定位为：
**一个基于合法官方数据源、以付费意愿与用户可进入性排序、每周输出 Top 10 需求假设及证据链报告的需求雷达系统。**

---

## 2. 产品目标与非目标

### 2.1 产品目标

1. 每日增量采集美国市场公开数据，主窗口滚动 4 周；
2. 抽取痛点、求助、招标、外包、采购等需求信号；
3. 按付费意愿强度 × 可进入性排序，输出 Top 10 需求主题；
4. 为每个需求生成详细报告，包含证据链、目标客户、现有替代方案、金额线索和验证实验；
5. 支持人工审核与反馈校准，逐步提高准确率；
6. 帮助用户把"需求假设"推进到"付费验证"。

### 2.2 非目标

- 不保证输出绝对真理，只输出"最值得验证的付费需求假设"；
- 初期不覆盖全球、不做全语言、不做全行业深度分析；
- 不自动完成真实付费验证，验证实验仍需人工执行；
- **不使用任何无官方 API / 授权的爬虫渠道**，宁可信号少也不碰合规红线；
- 不替代用户做最终商业决策。

## 3. 用户与使用场景

### 3.1 目标用户

- 创业者与独立开发者（MVP 核心用户）；
- 产品经理与增长负责人；
- 投资分析师与 VC/PE 研究员；
- 咨询顾问与市场研究员。

### 3.2 核心场景

每周一早上，用户收到一份美国市场 Top 10 付费需求报告。
用户从中选择 3–5 个需求，按照报告中的验证实验设计，联系目标客户、测试定价、要求付定金或签试点。
用户通过 Web 仪表盘回填验证结果，下一周系统据此校准权重。

## 4. 核心概念与定义

### 4.1 需求主题

将多条来自不同来源的信号，聚类为一个可描述的需求主题。
例如："中小企业 AI 合规审计"、"养老机构护理人员排班优化"。

### 4.2 付费意愿信号等级

| 等级 | 信号类型 | 典型来源 | 付费意愿 |
|---|---|---|---|
| P0 | 泛泛抱怨、情绪表达 | Reddit、App 评论 | 极低 |
| P1 | 求推荐、问"有没有人做" | 社区问答 | 低 |
| P2 | 比价、问预算、询价 | 评论、帖子 | 中低 |
| P3 | 外包发布、采购意向 | Freelancer.com、SAM.gov 意向 | 中高 |
| P4 | 政府招标、RFP、合同授予 | SAM.gov、USAspending | 高 |
| P5 | 已付费外包、预售 | Freelancer.com 已完成项目 | 很高 |

**P6（签试点、付定金、首单）不进排序公式**，作为用户回填的"验证结果"标签，仅用于反馈校准和报告标注（见 5.8）。

### 4.3 排序原则

- 候选池过滤：`P_max ≥ P3`；
- 候选池内按 `最终分 = WPS × 置信度 × 可进入性` 排序；
- 若候选主题不足 10 个，允许 P_max = P2 且信号密度高（见 5.5）的主题递补，报告中明确标注。

### 4.4 时间窗口

- **主窗口：过去 4 周滚动数据**（解决 P4/P5 信号稀疏问题）；
- **增量窗口：过去 1 周**，用于"新增/加速"标记和趋势确认；
- 基线：过去 12 周；
- 信号衰减：权重按周衰减（第 1 周 1.0，第 2 周 0.85，第 3 周 0.7，第 4 周 0.6）。

## 5. 数据源与采集

### 5.1 数据源分层（按合规可行性，2026-10 调研结果）

**Tier A — 官方免费 API / 开放数据（主力源）**

| 数据源 | 接入方式 | 信号等级 | 备注 |
|---|---|---|---|
| SAM.gov | Opportunities API v2 / Contract Awards API（免费 key） | P3–P4 | 非联邦 key 限 10 次/天，需注册实体（1000 次/天）或申请 system account；**FPDS 已于 2026-02 关停并入 SAM.gov** |
| USAspending.gov | 公开 REST API，免认证；另有 AWS 整库快照 | P4 | 支出明细分析，最友好 |
| CFPB 投诉数据库 | 公开 API + CSV 批量下载，免认证 | P0–P2 | **2026-08 起停止发布投诉叙述文本**，仅结构化字段 |
| Freelancer.com | 官方 REST API（OAuth，需申请审批） | P3–P5 | 唯一能批量拉"项目+出价"的外包平台；条款要求缓存 24h 刷新、不得转售数据 |
| App Store 评论 | Apple 官方 RSS/JSON 端点，免认证 | P0–P2 | 仅最近约 500 条/国家 |
| Google Play 评论 | 开源库 / 第三方托管 API（SerpApi 等） | P0–P2 | 灰色但实务被广泛接受，风险低 |

**Tier B — 官方付费 API（预算允许时启用）**

| 数据源 | 接入方式 | 信号等级 | 成本 |
|---|---|---|---|
| Reddit | Data API，商用 $0.24/千次起，企业约 $12k/年 | P0–P1 | MVP 先用免费非商用档验证（约 100 QPM），商用前需购授权 |
| Google Trends | 官方 API（alpha，申请制）或第三方托管 API | P0–P1 | 相对指数，无绝对量 |

**Tier C — 授权数据商（按需采购，不自建爬虫）**

- 招聘类信号：改用授权数据商（Coresignal 等转售职位数据）或官方开放统计（BLS/JOLTS），**不直接抓 LinkedIn / Indeed / Glassdoor**（三者均无公开数据 API，ToS 明确禁止爬虫，LinkedIn/Glassdoor 有诉讼与关停先例）。
- Trustpilot / G2 / Capterra：仅自有品牌可走付费官方 API；跨品牌数据走官方 data feed 商务洽谈（G2 已于 2026-01 收购 Capterra）。

**明确排除（无合法批量渠道）**

- LinkedIn Jobs、Indeed、Glassdoor、Upwork、Fiverr、Kickstarter、Indiegogo、BBB、Quora、TikTok。
- 理由：无官方数据 API 或已关停，ToS 明文禁止爬虫，反爬强且有封禁/诉讼先例。Kickstarter/Indiegogo 的 P5 众筹信号由 Freelancer.com 已完成项目和 SAM.gov 合同授予部分替代。

### 5.2 采集要求

- 只走 5.1 列出的渠道；任何新增源必须先过合规审查；
- 遵守 API 速率限制、robots.txt、GDPR/CCPA；
- 去标识化，不存储个人敏感信息（用户名哈希化，正文中的 PII 在清洗层脱敏）；
- 每条数据保留来源链接和时间戳；
- 支持增量采集与跨天去重（URL + 内容指纹双判重）；
- 数据保留期：原始文本 90 天，结构化字段与聚合结果不限期。

## 6. 信号抽取

对每条文本，抽取结构化字段。**付费信号判定规则优先、LLM 辅助**：

- 规则判定：招标编号、合同金额、时薪/年薪数字、预算区间（正则 + 实体识别）→ 直接定级 P3–P5；
- LLM 判定：痛点、人群、场景、紧急度、替代方案等语义字段；
- LLM 输出必须引用原文片段，无法引用的字段置空。

```json
{
  "国家": "美国",
  "来源": "SAM.gov",
  "时间": "2026-10-09T08:00:00Z",
  "人群": "中小企业主",
  "场景": "报税季",
  "痛点": "找不到靠谱会计师，等待超过2周",
  "现有方案": "自己用软件，失败后找外包",
  "成本线索": "预算500-2000美元",
  "紧急度": "高",
  "付费信号": "P3",
  "付费信号判定方式": "rule",
  "证据链接": "..."
}
```

重点识别：
- 付费信号：预算、报价、招标、外包、采购（规则）；
- 紧急信号：急、今天、马上、罚款、停业、截止（关键词 + LLM）；
- 供给不足：缺货、等待、排期、没人做、太贵、太慢（LLM）；
- 替代方案：Excel、人工、外包、竞品名（LLM）。

---

## 7. 主题聚类

- 使用 Embedding + 聚类算法，将相似信号聚合为需求主题；
- 每个主题生成名称、摘要、关键词；
- 同一主题跨周保留主题 ID，支持生命周期追踪（新增 / 加速 / 衰减 / 消失）；
- 支持人工合并、拆分、重命名，人工修正结果作为聚类评测样本回流。

**质量要求**：MVP 阶段每周人工抽检聚类结果，目标自动聚类可接受率 ≥ 70%（4 周后评估）。

---

## 8. 付费信号分级

- 自动判定每个主题的 `P_max`（规则判定优先）；
- 记录各等级信号的数量、来源、金额线索；
- 对 P3–P5 信号优先保留原始链接和金额信息。

---

## 9. 评分与排序

### 9.1 候选池过滤

`P_max ≥ P3`（不足 10 个时按 4.3 递补）。

### 9.2 付费意愿强度 WPS（全部归一化到 0–1）

```text
WPS = 0.35 * 信号等级强度
    + 0.25 * 信号密度
    + 0.15 * 信号多样性
    + 0.10 * 金额线索强度
    + 0.10 * 趋势持续性
    + 0.05 * 地域集中度
```

各分量定义：

- **信号等级强度**：`P_max` 映射，P5 = 0.85，P4 = 0.70，P3 = 0.55，P2 = 0.35（P2 仅递补时使用）；
- **信号密度**：主题内信号数（按 4.4 周衰减加权）除以候选池中位数，截断到 [0, 1]；
- **信号多样性**：主题覆盖的独立数据源数 / 5，截断到 [0, 1]；
- **金额线索强度**：有金额信号占比 × log(中位金额) 归一化；无任何金额线索时为 0；
- **趋势持续性**：主题出现在过去 N 周中的周数 / 4（新主题为 0.25）；
- **地域集中度**：信号州级分布的赫芬达尔指数（越集中越高；全国性主题取 0.5）。

### 9.3 置信度

```text
置信度 = 0.4 * min(证据数 / 10, 1)
       + 0.3 * min(独立来源数 / 3, 1)
       + 0.3 * 时间一致性
```

- 时间一致性：信号分布在 ≥ 2 个不同周为 1.0，全部集中在同一周为 0.5；
- 规则判定的 P3+ 信号每条额外 +0.05（封顶 0.15）。

### 9.4 可进入性（Accessibility）

衡量核心用户（创业者/独立开发者）对该需求的可执行性：

```text
可进入性 = 0.5 * 客户可达性 + 0.3 * 单笔规模适配 + 0.2 * 交付门槛（反向）
```

- 客户可达性：目标客户能否通过公开渠道直接联系（SMB/个人 = 1.0，企业 = 0.5，仅政府采购 = 0.2）；
- 单笔规模适配：金额线索中位数在 $1K–$50K 区间 = 1.0，$50K–$500K = 0.6，> $500K 或 < $1K = 0.3；
- 交付门槛：需要牌照/资质/重资产 = 低分。

### 9.5 最终排序

```text
最终分 = WPS × 置信度 × 可进入性
```

输出最终分最高的 Top 10。同时保留一份"纯 WPS 榜"供投资人类用户切换查看。

## 10. 报告生成

每个需求生成一份 Markdown/HTML 报告，包含：

- 需求名称与一句话摘要；
- 付费意愿等级、WPS、置信度、可进入性、最终分；
- 核心付费信号与证据链（每条结论绑定证据链接）；
- 目标客户、预算来源；
- 现有替代方案与不满点；
- 金额线索：招标金额、外包预算；
- 验证实验设计：落地页、访谈、预售、定金；
- 风险与下一步行动；
- **附录（明确标注"推测"）**：竞争格局初判、可能的决策人画像——LLM 生成、无证据链支撑的内容只允许出现在此节。

---

## 11. 人工审核

- 审核 Top 20，选出 Top 10；
- 过滤噪音、不可验证主题、合规风险；
- 修正聚类和付费信号等级；
- 审核结果全部结构化记录，用于反馈校准。

---

## 12. 反馈校准与回填机制

- **回填产品机制**：Web 仪表盘为每个报告主题提供"验证状态"流转（未验证 → 访谈中 → 落地页测试 → 预售/定金 → 已签单 / 已放弃），附结果备注；每周报告邮件中带一键回填链接；
- 记录人工修正、验证实验结果、真实付费数据（P6 标签）；
- 每月根据回填数据调整数据源权重、WPS 权重、置信度参数；
- 形成"发现 → 验证 → 校准"闭环。

---

## 13. 通知与导出

- 每周邮件推送 Top 10 报告；
- Web 仪表盘查看历史报告、回填验证结果；
- 支持导出 PDF、Markdown、CSV；
- 支持按行业、地区、付费等级筛选。

## 14. 系统架构

```text
官方 API / 开放数据 / 授权数据商（仅合规渠道）
        ↓
采集层：Prefect 调度，速率限制内置
        ↓
清洗层：去重、PII 脱敏、实体识别
        ↓
信号抽取层：规则引擎（付费信号）+ LLM（语义字段）
        ↓
主题聚类层：Embedding + 聚类（跨周主题 ID 追踪）
        ↓
评分排名层：P_max 过滤 + WPS + 置信度 + 可进入性
        ↓
报告生成层：RAG + LLM（结论必须绑定证据链接）
        ↓
人工审核 + 验证实验回填
        ↓
反馈校准权重
```

**推荐技术栈**
- 采集：Python、官方 API SDK；
- 调度：Prefect（MVP 不用 Airflow/Kafka，降低运维）；
- 存储：PostgreSQL + pgvector、S3；
- NLP：spaCy、sentence-transformers、LLM API；
- 前端：Next.js 或 Streamlit；
- 监控：Grafana + 采集失败告警。

**LLM 配置（2026-10-10 更新，实现见 extractor/llm.py `resolve_config`）**
- 双档：重量档 `OPENAI_API_KEY`/`OPENAI_BASE_URL`/`OPENAI_MODEL`（如 kimi-k2.7-code-highspeed，`source ~/.openai/model.kimi`）；轻量档 `NEEDRADAR_LLM_LIGHT`/`NEEDRADAR_LLM_LIGHT_MODEL`（本机 Ollama，`http://localhost:11434/v1` + `gemma4:12b`，免费）。两档互相回落，都未配置则纯规则跑通。
- **当前默认：全部 LLM 任务走本地 Gemma 4 e4b**（只配轻量档即可，`NEEDRADAR_LLM_LIGHT_MODEL=gemma4:e4b`）；切回 Kimi：source ~/.openai/model.kimi（重量档优先于轻量档用于抽取层；聚合裁决类始终优先轻量档）。
- 实测（2026-10-10）：e4b 抽取 JSON 合规 13/13、字段填充 71%、evidence 逐字 100%（代码强制）、约 18s/条；12b 填充 64%、25-30s/条；裁决层 e4b 与 12b/kimi 的存活主题与排序完全一致（barrier 分差 ≤0.05）；整次 run_rank e4b 3.2 分钟 vs 12b 7.7 分钟。**结论：e4b 质量相当、快约 2 倍，设为默认推荐**。

**市场**：美国

**时间窗口**：主窗口 4 周滚动 + 1 周增量
**行业**：不限

**数据源（全部为 Tier A 合规渠道）**：

- Freelancer.com API；
- CFPB 投诉数据库；

**输出**：
- 每周 Top 10 付费需求报告；
- 每份报告含证据链和验证实验；
- 人工审核后发布。

**运行周期**：
- 每日采集；
- 每周生成报告；
- 每月校准权重；
- 连续运行 4 周后评估效果。

## 17. 成功指标

**系统健康（产品可控）**
- 每周报告按时生成率 ≥ 95%；
- 采集成功率 ≥ 98%（按数据源计）。

**质量（核心指标）**
- **精排准确率**：Top 10 中被审核员判定"值得验证"的比例 ≥ 60%，逐月提升；
- **重复主题率**：相邻两周 Top 10 重复主题 ≤ 3 个（除非主题明确处于"加速"状态）；
- 聚类可接受率 ≥ 70%（每周抽检）。

**用户价值（观察指标，不作为产品验收门槛）**
- 每周人均回填验证状态 ≥ 2 个主题；
- 用户反馈"报告有帮助"比例 ≥ 70%；
- 4 周留存率 ≥ 50%。

## 19. 风险与对策

| 风险 | 对策 |
|---|---|
| 官方 API 配额不足（SAM.gov 非联邦 key 仅 10 次/天） | 注册实体提升配额；申请 system account；USAspending AWS 快照兜底 |
| Freelancer.com API 审批被拒 | 提前申请并说明"聚合分析"定位；被拒则降级为 SAM.gov/USAspending 单源 P3+ 信号 |
| Reddit 商用授权成本 | 验证期用免费档；商用前按调用量测算，成本超标则降为次要源 |
| 合规数据源信号总量不足 | 4 周主窗口 + P2 递补机制 + 授权数据商采购（Coresignal 等） |
| LLM 幻觉 | 规则优先判定 + 证据链接强制绑定 + "推测"附录隔离 + 人工审核 |
| 排名不稳定 | 4 周滚动窗口 + 12 周基线 + 周衰减平滑 |
| 成本失控 | 月度 $500 硬上限 + 超限自动降级 + 缓存 |
| 用户不回填 | 一键回填链接 + 验证状态流转产品化 + 每周邮件提醒 |
| 政府/大额主题霸榜 | 可进入性维度 + 双榜单（默认榜 vs 纯 WPS 榜） |
| 数据源政策变化（参考 FPDS 关停、CFPB 停发叙述、G2 收购 Capterra） | 每季度复核数据源合规状态与可用性 |

**总结**：
NeedRadar V0.2 在 V0.1 的基础上做了三个根本性修正：
1. **合规优先**——数据源全部限定在官方 API / 开放数据 / 授权渠道，宁可信号少也不碰爬虫红线；
2. **可实现**——WPS、置信度、可进入性全部给出工程可实现的定义；
3. **对核心用户可执行**——新增可进入性维度，避免报告被不可执行的大额政府招标霸榜。
它不追求"最紧缺"，而是寻找"最可能被付费解决、且用户够得着"的需求，并通过证据链、人工审核和验证回填，把需求假设推进到真实付费。
