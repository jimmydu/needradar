# NeedRadar 需求雷达 · 初始设计 PRD

**版本**：V0.1  
**状态**：草案  
**目标市场**：美国  
**时间窗口**：滚动 1 周  
**行业范围**：不限  
**排序依据**：付费意愿优先  
**输出**：每周 Top 10 需求报告 + 证据链 + 验证实验建议

---

## 1. 背景与问题

创业者、产品经理、投资人和咨询顾问需要发现“有人愿意付费解决”的需求，但现有方式存在明显问题：

- 人工搜索、访谈、看竞品，速度慢、主观性强、无法规模化；
- 24 小时窗口太短，公开数据中付费信号稀疏，噪音大；
- “紧缺”不等于“付费”，大量抱怨背后没有预算；
- 招聘、招标、外包、众筹等强付费信号分散在不同平台，难以聚合；
- 缺少从“信号发现”到“付费验证”的结构化流程。

因此，本产品定位为：  
**一个自动采集美国公开数据、以付费意愿排序、每周输出 Top 10 需求假设及详细报告的需求雷达系统。**

---

## 2. 产品目标与非目标

### 2.1 产品目标

1. 每周自动采集美国市场过去 1 周的公开数据；
2. 抽取痛点、抱怨、求助、招聘、招标、外包、众筹等需求信号；
3. 按付费意愿强度排序，输出 Top 10 需求主题；
4. 为每个需求生成详细报告，包含证据链、目标客户、现有替代方案、金额线索、竞争格局和验证实验；
5. 支持人工审核与反馈校准，逐步提高准确率；
6. 帮助用户把“需求假设”推进到“付费验证”。

### 2.2 非目标

- 不保证输出绝对真理，只输出“最值得验证的付费需求假设”；
- 初期不覆盖全球、不做全语言、不做全行业深度分析；
- 不自动完成真实付费验证，P6 级别仍需人工实验；
- 不采集非公开、隐私或违反平台 ToS 的数据；
- 不替代用户做最终商业决策。

---

## 3. 用户与使用场景

### 3.1 目标用户

- 创业者与独立开发者；
- 产品经理与增长负责人；
- 投资分析师与 VC/PE 研究员；
- 咨询顾问与市场研究员；
- 企业创新部门。

### 3.2 核心场景

每周一早上，用户收到一份美国市场 Top 10 付费需求报告。  
用户从中选择 3–5 个需求，按照报告中的验证实验设计，联系目标客户、测试定价、要求付定金或签试点。  
下一周根据真实反馈校准系统权重。

## 4. 核心概念与定义

### 4.1 需求主题

将多条来自不同来源的信号，聚类为一个可描述的需求主题。  
例如：“中小企业 AI 合规审计”、“养老机构护理人员排班优化”。

### 4.2 付费意愿信号等级

| 等级 | 信号类型 | 典型来源 | 付费意愿 |
|---|---|---|---|
| P0 | 泛泛抱怨、情绪表达 | Reddit、X、论坛 | 极低 |
| P1 | 求推荐、问“有没有人做” | 社区问答、群组 | 低 |
| P2 | 比价、问预算、询价 | 评论、帖子、私信 | 中低 |
| P3 | 招聘岗位、外包发布 | LinkedIn Jobs、Indeed、Upwork | 中高 |
| P4 | 政府招标、采购意向、RFP | SAM.gov、FPDS | 高 |
| P5 | 众筹成功、预售、已付费外包 | Kickstarter、Upwork 已完成项目 | 很高 |
| P6 | 签试点、付定金、首单 | 需人工验证 | 最高 |

### 4.3 排序原则

- 先按最高付费信号等级 `P_max` 过滤；
- 只有 `P_max ≥ P3` 的主题进入 Top 10 候选池；
- 在候选池内按付费意愿强度评分 `WPS` 排序；
- 最终分 = `WPS × 置信度`。

### 4.4 时间窗口

- 主窗口：过去 1 周滚动数据；
- 基线：过去 4 周、12 周；
- 24 小时数据仅用于趋势确认，不作为主排序依据。

## 5. 功能需求

### 5.1 数据采集

系统需支持从以下美国数据源自动采集公开数据：

**一级信号源（P3–P5，权重最高）**
- LinkedIn Jobs、Indeed、Glassdoor；
- SAM.gov、FPDS；
- Upwork、Fiverr、Freelancer；
- Kickstarter、Indiegogo。

**二级信号源（P2，权重中等）**
- Trustpilot、BBB、CFPB 投诉数据库；
- G2、Capterra、App Store、Google Play 评论；
- Reddit、Quora、行业论坛。

**三级信号源（P0–P1，权重低）**
- Google Trends、X、TikTok 公开话题。

**采集要求**
- 遵守 robots.txt、API ToS、GDPR/CCPA；
- 去标识化，不存储个人敏感信息；
- 每条数据保留来源链接和时间戳；
- 支持增量采集与去重。

### 5.2 信号抽取

对每条文本，使用 LLM + NLP 抽取结构化字段：

```json
{
  "国家": "美国",
  "来源": "Upwork",
  "时间": "2026-10-09T08:00:00Z",
  "人群": "中小企业主",
  "场景": "报税季",
  "痛点": "找不到靠谱会计师，等待超过2周",
  "现有方案": "自己用软件，失败后找外包",
  "成本线索": "预算500-2000美元",
  "紧急度": "高",
  "付费信号": "P3",
  "证据链接": "..."
}
```

重点识别：
- 付费信号：预算、报价、招聘、招标、外包、众筹；
- 紧急信号：急、今天、马上、罚款、停业、截止；
- 供给不足：缺货、等待、排期、没人做、太贵、太慢；
- 替代方案：Excel、人工、外包、竞品名。

### 5.3 主题聚类

- 使用 Embedding + 聚类算法，将相似信号聚合为需求主题；
- 每个主题生成名称、摘要、关键词；
- 支持人工合并、拆分、重命名。

### 5.4 付费信号分级

- 自动判定每个主题的 `P_max`；
- 记录各等级信号的数量、来源、金额线索；
- 对 P3–P5 信号优先保留原始链接和金额信息。

### 5.5 评分与排序

**候选池过滤**  
`P_max ≥ P3`

**付费意愿强度 WPS**

```text
WPS = 0.35 * 信号等级强度
    + 0.25 * 信号密度
    + 0.15 * 信号多样性
    + 0.10 * 金额线索强度
    + 0.10 * 趋势持续性
    + 0.05 * 地域集中度
```

信号等级强度映射：
- P6 = 1.0
- P5 = 0.85
- P4 = 0.70
- P3 = 0.55

**置信度**

```text
置信度 = f(证据数量, 来源多样性, 时间一致性)
```

**最终排序**

```text
最终分 = WPS × 置信度
```

输出最终分最高的 Top 10。

### 5.6 报告生成

每个需求生成一份 Markdown/HTML 报告，包含：

- 需求名称与一句话摘要；
- 付费意愿等级与最终分；
- 核心付费信号与证据链；
- 目标客户、预算来源、决策人；
- 现有替代方案与不满点；
- 金额线索：招标金额、薪资、外包预算、众筹金额；
- 竞争格局与空白点；
- 验证实验设计：落地页、访谈、预售、定金；
- 风险与下一步行动。

### 5.7 人工审核

- 审核 Top 20，选出 Top 10；
- 过滤噪音、不可验证主题、合规风险；
- 修正聚类和付费信号等级；
- 审核结果用于反馈校准。

### 5.8 反馈校准

- 记录人工修正、验证实验结果、真实付费数据；
- 每月调整数据源权重、WPS 权重、置信度参数；
- 形成“发现 → 验证 → 校准”闭环。

### 5.9 通知与导出

- 每周邮件推送 Top 10 报告；
- Web 仪表盘查看历史报告；
- 支持导出 PDF、Markdown、CSV；
- 支持按行业、地区、付费等级筛选。

## 6. 系统架构

```text
数据源 API / RSS / 爬虫
        ↓
采集层：Airflow / Prefect / Kafka
        ↓
清洗层：去重、语言检测、翻译、实体识别
        ↓
信号抽取层：LLM + NLP
        ↓
主题聚类层：Embedding + 聚类
        ↓
评分排名层：P_max 过滤 + WPS + 置信度
        ↓
报告生成层：RAG + LLM
        ↓
人工审核 + 验证实验
        ↓
反馈校准权重
```

**推荐技术栈**
- 采集：Python、Playwright、Scrapy、官方 API；
- 调度：Airflow / Prefect；
- 存储：PostgreSQL + pgvector、ClickHouse、S3；
- NLP：spaCy、sentence-transformers、OpenAI/Claude；
- 检索：Elasticsearch / pgvector；
- 前端：Next.js 或 Streamlit；
- 报表：Metabase + LLM；
- 监控：Grafana。

## 7. MVP 范围

**市场**：美国  
**语言**：英语  
**时间窗口**：滚动 1 周  
**行业**：不限  
**数据源**：
- LinkedIn Jobs、Indeed；
- SAM.gov、FPDS；
- Upwork；
- Kickstarter；
- Reddit；
- Trustpilot、G2。

**输出**：
- 每周 Top 10 付费需求报告；
- 每份报告含证据链和验证实验；
- 人工审核后发布。

**运行周期**：
- 每日采集；
- 每周生成报告；
- 每月校准权重；
- 连续运行 4 周后评估效果。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 每日采集与处理在 6 小时内完成 |
| 可用性 | 每周报告按时生成，失败可重试 |
| 合规 | 遵守 GDPR/CCPA、平台 ToS、robots.txt |
| 安全 | 数据加密、访问控制、审计日志 |
| 可扩展 | 支持后续增加国家、语言、行业 |
| 成本 | MVP 阶段 LLM 与 API 成本可控 |
| 可解释 | 每条结论必须绑定证据链接 |

---

## 9. 成功指标

- 每周报告按时生成率 ≥ 95%；
- 人工审核通过率 ≥ 60%；
- Top 10 中至少 3 个进入真实验证实验；
- 验证实验中至少 1 个获得付费定金或试点合同；
- 用户反馈“报告有帮助”比例 ≥ 70%；
- 付费信号准确率逐月提升。

## 10. 里程碑

| 阶段 | 时间 | 交付 |
|---|---|---|
| 第 1 周 | 数据源接入 | LinkedIn、SAM.gov、Upwork、Kickstarter 跑通 |
| 第 2 周 | 信号抽取与聚类 | 结构化字段 + 主题聚类 |
| 第 3 周 | 评分与报告 | WPS 排序 + Top 10 报告模板 |
| 第 4 周 | 人工审核与校准 | 首份报告 + 反馈机制 |
| 第 5–8 周 | MVP 运行 | 连续 4 周报告 + 验证实验 |
| 第 9 周 | 复盘 | 决定扩展或调整 |

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 数据源限制或封禁 | 优先官方 API，遵守 ToS，准备备用源 |
| LLM 幻觉 | RAG + 证据链接 + 人工审核 |
| 付费信号稀疏 | 1 周窗口 + 多源聚合 + P_max 过滤 |
| 排名不稳定 | 滚动窗口 + 4 周基线 + 平滑算法 |
| 合规风险 | 去标识化、数据保留期、隐私审查 |
| 成本过高 | 分级采集、缓存、按需调用 LLM |
| 用户不验证 | 报告内置验证实验模板和下一步行动 |

**总结**：  
NeedRadar V0.1 是一个聚焦美国、滚动 1 周、以付费意愿排序的需求雷达。  
它不追求“最紧缺”，而是寻找“最可能被付费解决”的需求，并通过证据链、人工审核和验证实验，把需求假设推进到真实付费。
